# Token savings plan

Goal: reduce what llm_light spends per turn without hurting answer quality.
Work the levers in order. Change one at a time and measure before and after.
A lever ships only when its measurement shows a gain.

## Levers

- [x] **1. Keep the prompt cache warm.** Avoid switching models between consecutive turns, since a switch may pay a fresh cache write. Check whether a stronger model is worth that write on the next turn.
  - Answered from the Claude API docs (prompt caching, invalidation hierarchy): the cache is scoped per model, and a top-level `effort` change invalidates the cached history on every model and the cached tools and system prompt on some. Not checked against the live API.
  - Effort: shipped. The top-level effort is fixed at `BASE_EFFORT` and the routed effort goes in an effort-only system message (beta `mid-conversation-output-config-2026-07-01`), so effort changes keep the cache.
  - Model: routed once per session by default. A session that keeps its strongest model (only moving up a tier) cost 48% to 67% more in `benchmark_session_cache.py`, because most questions route to Haiku. Keeping the first question's model (`ROUTE_ONCE`, the default; `LLM_LIGHT_ROUTE_ONCE=0` turns it off): +71% when the session opens on Sonnet, -91% when it opens on Haiku, at the price of answering hard questions on Haiku. See Results.
- [x] **2. Confirm LLMLingua is running.** Done: the CPU-only torch build could not load the model (llmlingua defaults to CUDA), so nothing compressed. Fixed; a 2,537-token sample compressed to 1,324. It is a silent no-op until `pip install llmlingua`. Check that `LLMLINGUA_MIN_TOKENS` (default 800) is low enough to trigger on typical retrieval sizes.
- [x] **3. Lower the retrieval budget where answers are short.** `_RETRIEVAL_BUDGET` is set by effort (low 1500, medium 3000, high 6000, max 9000). Measured offline with `benchmark_models.py --budgets`: going below the current budgets loses answers, so nothing changed. See Results.
- [x] **4. Tighten escalation.** Measured offline with `benchmark_router.py`: no query on the repo set lands in the band that `ROUTER_ESCALATE_MARGIN` can change, at any margin tried. Nothing changed. See Results.
- [ ] **5. Route large file reads to a cheaper model (Spotify-style).** Only after measuring how many tokens go to agent or tool reads. Targets: API mode `tools.py` `read_file`; subscription mode needs a settings-file hook. Files needed for a SEARCH/REPLACE edit must stay exact.
  - Status: not changed. The read-token count needs live API runs in API mode, which this offline pass did not make.
- [x] **6. Trim the CLI providers' own prompts.** Gemini and Codex have no cache llm_light controls, so whatever their CLI adds in front of llm_light's prompt is paid on every question.
  - Codex: shipped. Its agent instructions are replaced by a no-tools note (`-c model_instructions_file`) and its skills, permissions, collaboration-mode and environment sections and twelve unused tool features are switched off with `-c` keys. Measured live with `benchmark_cli_providers.py`. See Results.
  - Gemini (agy): not measured yet. agy's stream-json output has not been checked for a usage figure.
- [x] **7. Offer the subscription agent only the tools it can use.** Shipped. Without a `--tools` list the CLI sends every built-in tool schema on every model round. See Results.
- [x] **8. Keep doc excerpts only where the model cannot open the file.** Shipped for Claude; Gemini and Codex keep them. See Results. Indexing `.md` for retrieval, which might let those two drop them as well, is #180.
- [x] **9. Send the Windows prompt on stdin, not as an `@file` mention.** Shipped, mainly as a bug fix: past 24k to 34k tokens the mention lost the whole prompt. See Results.
- [x] **10. Send the routed effort on the subscription path.** Measured and rejected: it saves tokens and loses answers. See Results.

## How to measure

- Use `/cost` and the stats file `~/.llm_light_stats.json` before and after each change.
- Run the same set of questions each time, and record: input tokens, cached tokens, output tokens, cost, and turns per question.
- Offline, without an API key: `python tests/benchmarks/benchmark_models.py --budgets` (recall and tokens per effort budget) and `python tests/benchmarks/benchmark_router.py` (tier and model per question, with `--margin` to replay another escalation margin). Both measure routing and retrieval, not answer quality. `python tests/benchmarks/benchmark_session_cache.py` prices a session of the repo questions under three routing policies with a prompt-cache model; it is a model with stated assumptions, not a measurement of live usage.
- Keep a result line per lever here once measured.

## Decisions

- Doc excerpts stay for Gemini and Codex (lever 8). Leaving them out would save about 20,000 input tokens per question there, but those two cannot open a file, and without excerpts they lost 7 of 10 doc questions and won none. Code questions were even (2 wins, 3 losses, 4 ties, 9 of 10 run). That trade is not taken without a way to reach docs on those providers (#180).
- `LLMLINGUA_MIN_TOKENS` stays at 800 (now settable with `LLM_LIGHT_LLMLINGUA_MIN_TOKENS`). Every retrieval budget is 1 500 or more, so a full retrieval always qualifies.
- Retrieval budgets stay as they are (lever 3). Low loses answers against medium in both runs (2026-10-30: 13/25 against 20/25 identifier, 10/12 against 11/12 paraphrase). High added two identifier answers over medium in the first run, but none in the 2026-10-30 re-run, where it sends 57% more mean tokens (2,842 against 1,811) for the same 20/25 and 11/12. That makes high a candidate to lower, on a difference of one or two questions and without answer-quality scoring, so it was left for a decision in #77. The answer-quality run (docs/BENCHMARKS.md, section 2f) settled it: equal quality, and the rendered context differs by 2%, so the budgets stay.
- `ROUTER_ESCALATE_MARGIN` stays at 0.15 (lever 4). Only scores between 12.0 and 12.0 × (1 + margin) change tier, and no repo question scores there. A larger margin would move questions off Opus on no evidence.
- Pinning a session to its strongest model is rejected (lever 1). It would raise answer quality on Haiku-routed questions, but on cost it loses by about half again.
- Keeping the first question's model is the default, by the developer's decision rather than a measured gain: the measurement is mixed, and this plan's rule is otherwise to ship only measured gains. Whichever question comes first decides both its cost and its quality: a Sonnet opener costs 71% more, a Haiku opener saves 91% by running hard questions on Haiku.
- Call-graph expansion is removed (#86). It sent 20-28% more tokens for no extra right-file hit, and on live answer quality it split 2 to 2 for 92% more context. `fetch_chunk` still gives the model callers and callees when it asks for them.
- `WORKTREE_BOOST` is 1.0, up from an untuned 0.5. It is the largest value that lost nothing when an unrelated file was the modified one.
- Max budget (9 000): not changed. In the first run max did not beat high on recall and sent about 700 more mean tokens (3,443 against 2,732); in the 2026-10-30 re-run it found two more identifier answers (22/25 against 20/25) for 825 more mean tokens (3,667 against 2,842). No repo question routes to max, so that result says nothing about the questions that do. Measure with max-tier questions before lowering it.
