# Changelog

All notable changes to `llm-light` are listed here. Versions follow [Semantic Versioning](https://semver.org/); until 1.0, a minor version may change behaviour.

## [Unreleased]

### Added

- **`!!command` runs a program that needs the terminal (#195).** An editor, a REPL or `git rebase -i` failed under `!`, which closes stdin and captures output. `!!` hands it the terminal with no timeout, and nothing goes to the model.
- **More of what you expect from a prompt.** `\`+`enter` adds a line where `alt+enter` is taken, `ctrl+g` edits the prompt in `$EDITOR`, and `/vim` switches to vi keys. Tab completes `/model` and `/permissions` values. `@order` now finds `src/deep/order_service.py` from anywhere in the project, ranking a match in the file name first, so you no longer type the folders. `ctrl+r` and `ctrl+l` already worked, and are now in `/help` and pinned by tests.
- **Use it from scripts.** `-p --output-format json` prints one result object when the turn ends and `stream-json` prints one object per line as it happens, with the field names `claude -p` uses; everything else goes to stderr. `git diff | llm-light -p "review this"` now sends the piped text with the question, where it used to be dropped silently. `-c -p "..."` answers in the saved conversation. `NO_COLOR` turns off the colour codes llm_light writes itself, as it already did for rich and prompt_toolkit. Checked live on the subscription with Haiku: piped text reached the model, `stream-json` arrived piece by piece, a follow-up with `-c` recalled a codeword from the turn before, and a bad key gave `is_error` and exit 1.
- **`/allow` and `/disallow` change what the agent may run, without a restart.** The agent's shell could only be set by `--allow-command` at startup, so finding out mid-task that it could not run your tests meant quitting. `/allow python -m pytest` applies from the next turn, also in a resumed CLI session, and is remembered for this project outside the repo, so a cloned repo cannot grant itself commands. Saved prefixes are named at each start. Checked live on the subscription with claude 2.1.317: after `/allow` the agent ran the command, and after `/disallow` a command that leaves a marker file did not run.
- **`/loop` repeats a question.** `/loop 3 <question>` asks up to 20 times in a row; `/loop 5m <question>` asks again 5 minutes after each turn ends, up to 20 turns. It takes `@file` mentions, queued `!command` output and your own `/commands`. Ctrl+C, a failed turn or a reached `/budget` stops it.
- **Send the model traffic through a proxy, such as the llm-fw firewall.** `--proxy URL` and `--proxy-ca PATH` (or `LLM_LIGHT_PROXY` and `LLM_LIGHT_PROXY_CA`) route the Anthropic client and the `claude`, `codex` and `agy` CLIs through an HTTPS proxy and trust its CA on top of the public roots; `--llm-fw` uses a local llm-fw's defaults. Embedding-model downloads, git and agent commands keep their own connection. `--proxy` wins over an `HTTPS_PROXY` already in the environment, which `llm-fw setup` sets. Without `--proxy-ca` the Anthropic client keeps its default trust, the OS store. `certifi` is now a declared dependency (it was already installed through `requests`).
- **Your own slash commands (#135).** Each `~/.llm_light/commands/<name>.md` becomes `/<name>`: its body is sent as the question, with `$ARGUMENTS` replaced by what you type after the name. They show in `/help` and the `/` menu (an optional frontmatter `description:` describes them). A repository's own `.llm_light/commands/` is not read, since it would be prompt text a cloned repo controls.
- **`/resume` and `--resume` pick an earlier conversation (#136).** `/clear` now keeps the conversation it ends instead of deleting it; `/resume` (or `--resume` at startup) lists this project's saved conversations with their date, turn count and first question, and switches to the one you pick. The newest 10 per project and provider are kept, still in `~/.llm_light_sessions`. `--continue` still resumes the latest.
- **`/rewind` goes back to before an earlier turn (#134).** It lists this run's turns; picking one truncates the conversation to before it and resets the files to the commit HEAD was at then, with `git reset --keep`. Like `/undo` it refuses, changing nothing, when a commit since is not a `Claude:` one or a file it would reset has local edits. Edits the agent left uncommitted are not restored.

### Fixed

- **`-p` now exits non-zero when an edit never lints.** After 3 attempts with syntax errors it applied nothing and exited 0, so a script took it for success.
- **A long subscription prompt no longer fails on Linux and macOS (#183).** The prompt and the system prompt went to the `claude` CLI as command-line arguments, and Linux refuses one argument over 131,072 bytes, so a long conversation or a large attachment ended the turn with `Argument list too long`. Both now take the route Windows already used: the prompt on stdin, the system prompt from a file. On Linux a 500 kB prompt with a 200 kB system prompt failed before and arrived whole after, through a stand-in for the CLI, since no signed-in `claude` was available on Linux or macOS.
- **On Windows, `!command`, `/run` and the API-mode `shell` tool now run in Git Bash, like the agent (#193).** They ran in `cmd.exe`, so one line could work for the agent and fail when typed: `echo $((40+2))` printed itself instead of 42. Without Git for Windows they stay on `cmd.exe`, where the `shell` tool refuses `%` as it refuses `$`. `LLM_LIGHT_SHELL=cmd` keeps `cmd.exe`, so `cmd` built-ins such as `type` need it, or `cmd /c type x`, and `/status` shows the shell in use.
- **Ctrl+C during `!command` or `/run` no longer ends the session.** It quit llm_light; it now stops the command and everything it started, and returns to the prompt. Checked with a real console Ctrl+C on Windows: `main` exited, this returned to the prompt within 0.25 s.
- **`!command` and `/run` show output as it arrives, and cannot hang the prompt.** The output only appeared when the command ended. On Windows a timeout killed only the shell, so a 1 s timeout on a 30 s command took 30 s and a chatty command never timed out. A command waiting for input hung with nothing on screen; stdin is now closed. A background child holding the pipe no longer holds up the prompt.
- **`/run` offers to log in when the login has expired**, as a typed question does, instead of ending the session with a traceback.
- **`/help` shows command arguments.** Rich read `[n]`, `[file]`, `[name]` and `[mode]` as markup and dropped them, so it listed a bare `/copy`, `/export`, `/model` and `/permissions`.
- **Ctrl+C at the prompt clears what you typed.** It quit and lost the text. On an empty prompt it still quits.

### Changed

- **The prompt comes up about 300 ms sooner (#192).** `llm_light.py --version` fell from a median of about 755 ms to 465 ms on Windows with Python 3.12 (15 warm runs per arm, two alternating rounds against `main`). `numpy`, `tqdm`, the markdown stack, `pygments` and watchdog's observers now load when first used, and the file watcher starts off the prompt's thread, so a large tree no longer delays the prompt either. `prompt_toolkit` still loads first, so the 100 ms goal in the issue is out of reach. The first reply and the first retrieval pay their own import once, next to a model call.
- **Subscription turns continue one `claude` CLI session, for 25% lower cost per session.** Each turn used to flatten the history into one text block and start a new CLI process, so the whole history was written to the cache again and the files the agent had read were forgotten. Now later turns use `--resume` and send only the new message. Over 8 paired six-turn sessions on Sonnet, API-equivalent cost fell from $0.3262 to $0.2446 (-25%), cache writes 42% and tool calls 16%. **Total input tokens rose 44%**, because a resumed session keeps what it read and cache reads rose 63%; how the subscription's limits count those is not published (#185). Judged by Opus in both orders over 48 turns: 6 wins, 8 losses, 34 ties. A resumed turn names the files that changed outside the conversation, because the session otherwise answered from memory: `LIMIT is 42` of a file that said 77. Outside a git repository, turns do not resume, and a turn more than 55 minutes after the last one starts over, since by then a resume would write the whole session to the cache again ($0.2066 against $0.0188 for a one-word turn on a session holding one large read). `LLM_LIGHT_CLI_RESUME=0` turns it off. `--resume` was removed in April for hanging on a 46k-token session and for resuming another project's session; a resume at 140,053 tokens took 5.3 s, and each run now has its own isolated home.
- **On Windows, a long subscription prompt no longer vanishes.** The prompt went to the `claude` CLI as an `@file` mention. Past a size between 24k and 34k tokens the CLI dropped the file with no error, question included, and the model saw only a file path: a 2,500-line prompt reached it as 498 tokens. A long conversation or a large `@file` or `!command` attachment could reach that size. The prompt now goes on stdin, which delivered a 12,000-line prompt whole. Smaller prompts also lose the fake `Read` wrapper and a line number on every line, about 204 tokens per call on 5 real prompts.
- **With Claude, the skeleton carries only `CLAUDE.md`, `AGENTS.md` and the root `README` (#142).** Other docs stay in the directory tree and the model opens them when a question needs them. On this repo the skeleton goes from 15,952 to 3,564 tokens, and mean total input per question falls about 55%, measured live on the subscription (76,634 to 34,772 on code questions, at Sonnet prices $0.0353 to $0.0310). Answers did not suffer: judged by Opus in both orders, 6 wins, 0 losses and 4 ties on 10 questions only the docs can answer, and 1 win, 1 loss, 7 ties and 1 invalid on 10 code questions. API-key mode was only modelled (-19% per session). Gemini and Codex cannot open files, and without the excerpts they lost 7 of 10 doc questions, so they keep every excerpt.
- **A subscription turn sends about 11,000 fewer input tokens per model round.** llm_light never limited the `claude` CLI's tools, so every round carried all 25 built-in schemas. It now sends a `--tools` list of what the mode can use: reading and editing files, a shell only where allowed, `NotebookEdit` only in a project with notebooks, the web tools only in bypass. Over 36 runs of 6 repo questions, mean total input fell 99,052 to 79,769 (-19%) and Sonnet-priced cost $0.0443 to $0.0369 (-17%). On 10 questions judged by Opus in both orders, the list won 4, every tool won 1, and 5 tied. **The agent can no longer start subagents, run skills or schedule jobs**, which it could before, with no prompt, on turns that read untrusted repo text. API-key requests are unchanged.
- **The proxy docs now say what agy really does (#153).** They said agy on Windows trusts only the OS certificate store. It trusted a private CA given with `--proxy-ca` and refused the same certificate without it (agy 1.4.12). They now also warn that a stock llm-fw only tunnels agy's model host: the turn works and shows on the dashboard, `inspected` is `false`, and nothing is scanned until `extraTargets` in `~/.llm-fw/config.json` lists it. No behaviour changed.
- **Gemini keeps your agy sign-in on macOS and on Linux without a keychain (#124).** Since agy started running with an empty home directory, a signed-in user on those platforms would be told to sign in, and signing in could not help. On macOS the login keychain could not be found under the redirected home (`security` exit 44, macOS 26.6.2); on Linux without a Secret Service agy looks for a token file under it. llm_light now links `Library/Keychains` on macOS and copies that one token file, and brings nothing else over, so plugins, hooks and MCP servers stay out. Checked with the real `security` tool on a macOS runner and with a trace of the real agy on Linux; no signed-in agy on either platform was available, so a real answered turn there is still to confirm.
- **An API error now reads as the API's own message.** A 400 or 401 in API-key mode printed the SDK's repr of the whole response body. It now prints `Claude API error 400: <message> (request <id>)`, which is also what a zero-data-retention org sees when it picks Fable 5.1 (#92). Tested through the real SDK against a stub; no such org was available, so the wording of that 400 is unverified.
- **Gemini can no longer search the web with your code, and sends about 6,500 fewer input tokens per question.** No agy permission kind stopped its `search_web` tool, so a Gemini turn could put the skeleton, retrieved code or the question into Google web-search queries (#122). agy now runs as a custom agent with no tools (`excludeDefaultComponents`), which also drops agy's own agent prompt. On a prompt that asks for a web search (agy 1.4.12) the default agent ran `search_web` 3 times; the new one ran no tool in 5 of 5 runs. If a search ever runs anyway, the turn fails instead of answering. On a repo question, input tokens fell from 11,078 to 4,072 (5 runs each); on a hard step-by-step question input fell from 11,094 to 4,600 but output rose from 12,537 to 16,239, all of it thinking (#149, `docs/BENCHMARKS.md` section 2e).
- **Untracked `.md` files stay out of the prompt.** In a git repository the skeleton now carries only the `.md` files git tracks (staged ones included), so a local plan or draft you have not added is no longer sent, and no longer paid for, on every turn and cache write. The directory tree still lists it. On this repo two local drafts were 699 tokens of a 17,576-token cached prefix, and a modelled 43-question session cost 1.1% less (`benchmark_session_cache.py`). Outside a git repository every `.md` file still goes in (#142).
- **Codex sends about half the tokens per question.** llm_light replaces codex's own agent instructions with a short no-tools note and switches off the codex prompt sections and tool features an answer engine never uses. On one repo question (5 runs each, codex-cli 0.166.0) input tokens fell from a mean of 21,766 to 9,190 and output from 926 to 621, and the trimmed runs took no hidden extra model rounds. `tests/benchmarks/benchmark_cli_providers.py` measures it; see `docs/BENCHMARKS.md`, section 2e.
- **Gemini turns show their token counts (#159).** agy reports usage on its result event, so the turn line, `/cost`, the exit footer and the status bar now show Gemini's input, cached and output tokens, as they do for codex, instead of `tokens, cost and caching unavailable for gemini`. No dollar figure: Gemini's prices are not Claude's.
- **Codex turns show their token counts.** The turn line, `/cost`, the exit footer and the status bar show the input, cached and output tokens codex reports, instead of `tokens, cost and caching unavailable for codex`. No dollar figure: codex's prices are not Claude's, so nothing is added to the session cost or the lifetime dollar savings.

### Removed

- **Call-graph retrieval expansion (`LLM_LIGHT_CALLGRAPH`) is gone (#86).** It was off by default. It never sent an answering file retrieval had missed, it added 20-28% more tokens, and in a live answer-quality run (`benchmark_answer_quality.py`) it won 2 and lost 2 of 8 how-is-X-used questions for 92% more context. `fetch_chunk` still lists a function's callers and callees on request.
- **The `claude_light` names are gone (#119).** The `claude-light` command, `claude_light.py`, the `CLAUDE_LIGHT_*` environment variables and the `~/.claude_light_*` home files are no longer read or copied; 0.1.0 kept them for one release. Run `llm-light`, rename the variables to `LLM_LIGHT_*` and the files to `~/.llm_light_*`. Startup prints one line for each old setting or file it still finds, so a renamed-away `CLAUDE_LIGHT_PROXY` does not silently stop routing traffic through the proxy.

## [0.1.0]

The first release on PyPI, as `llm-light-cli`: `pipx install llm-light-cli` or `uv tool install llm-light-cli`. The command is still `llm-light`. It needs Python 3.12 or newer, and the first install downloads PyTorch (about 1.5 GB) through `sentence-transformers`.

### What it does

- **Interactive and one-shot CLI** (`llm-light`, with `claude-light` kept as an alias) for asking about and editing the codebase in the current directory. Questions can be typed, passed as an argument or piped in; `--continue` resumes the project's previous conversation.
- **Providers**: Claude (default; API key or Pro subscription through `claude auth login`), Gemini through the Antigravity CLI `agy`, and Codex through `codex login`, chosen with `--provider`.
- **Retrieval**: tree-sitter splits Java, Python, Go, Rust, JavaScript and TypeScript into one chunk per method. Each question gets the top-K chunks from a hybrid static and dense index, and the agent can fetch more with `fetch_chunk`.
- **Prompt caching**: the project skeleton sits in a cached system prompt, with cache breakpoints after the history and the retrieved chunks. In API-key mode the cache is warmed once per TTL, and only for the model the turns use.
- **Routing**: each question goes to Haiku, Sonnet or a top tier (asked first), and the first turn's model is kept for the session. `--model` pins a model, and `/budget` caps spend.
- **Editing**: edits are lint-checked, shown as a diff and auto-committed as `Claude: [summary]`. `/undo` reverts the last such commit. Permission modes are `default`, `acceptEdits` (`-y`), `plan` and `bypassPermissions` (`--dangerously-skip-permissions`).
- **Shell**: the agent runs only commands that start with an `--allow-command` prefix. Commands that chain, pipe, redirect or substitute are refused.
- **Optional prompt compression** with LLMLingua: `pipx install "llm-light-cli[llmlingua]"`.
