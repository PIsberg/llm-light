# Changelog

All notable changes to `llm-light` are listed here. Versions follow [Semantic Versioning](https://semver.org/); until 1.0, a minor version may change behaviour.

## [Unreleased]

### Added

- **`--effort` and `--budget` flags (#327).** `--effort low|medium|high|max` pins the effort from the start, as `/effort` does, and `--budget <dollars>` starts the session with a spend cap, as `/budget` does. Both beat `~/.llm_light/settings.json`, and a provider without effort (Gemini, Codex) or without dollar pricing says it ignores them. A budget applies once spending reaches it, so it moves later questions of a session or a `/loop` to the cheapest model but cannot stop a single `-p` answer partway. Shell completion offers both.
- **SessionStart and SessionEnd hooks run with an API key (#311).** Only a subscription ran them, through the claude CLI. A `SessionStart` hook now runs when a conversation starts, with `source` `startup`, `resume` (`--continue`, `--resume`) or `clear` (after `/clear`), and what it prints goes with your next question, never into the cached system prompt. `SessionEnd` runs when one ends, with `reason` `clear`, `prompt_input_exit` (exit, Ctrl+D or Ctrl+C at the prompt) or `other` (SIGTERM, and the end of a `-p` run). A matcher selects by source or reason, as in Claude Code. `Notification` still runs only on a subscription (#311).
- **The read-only tool calls of one round run at the same time, with an API key (#196).** When the model asked for several `read_file`, `grep`, `list_files` or `fetch_chunk` calls in one round, they ran one after another. A round made only of those now runs them in parallel (up to 8), and the results go back in the order they were asked for. A round with `shell` or an MCP tool stays in order, since one call may depend on another and an MCP call may stop to ask you. Three 0.4 s calls took 1.2 s before and about 0.4 s now in the test; how often a live round has several calls was not measured (#85).
- **An MCP tool's image reaches the model, with an API key (#222).** An image in a tool result (a screenshot, a chart) reached the model as `[image/png image omitted]`. Up to five images per result now go as image blocks, with the `@image` limits: at most 5 MB, PNG, JPEG, GIF or WebP, the type read from the bytes. Others, audio and binary resources are still named, not sent. The omitted note now names the real media type; it read the SDK's `mimeType` under the wrong attribute name. On a subscription the claude CLI already handled images.
- **UserPromptSubmit, Stop and PreCompact hooks run with an API key (#226).** Only `PreToolUse` and `PostToolUse` ran outside a subscription. A `UserPromptSubmit` hook now runs before each question: exit 2 (or JSON `decision: "block"`) refuses it with the hook's message and nothing is sent, and what it prints, or its `additionalContext`, goes with the question. `Stop` runs after a completed turn and `PreCompact` before compression (`auto`, or `manual` for `/compact`); both are informational. `SessionStart`, `SessionEnd` and `Notification` still ran only on a subscription (#311).
- **A held-out question set for the retrieval benchmark (#287).** `tests/benchmarks/benchmark_models.py --fixture tests/fixtures/repo_questions_heldout.json` runs 14 paraphrases and 12 off-topic questions the floors were never tuned on, without re-embedding the repository. Re-sweeping `HYBRID_MIN_SCORE` on the body-first vectors (#264) with it kept the floors: 0.24 / 0.23 sends nothing for all 6 off-topic tuning questions (from 4) but changes nothing on the held-out set (still 10 of 12, 11 of 14 paraphrases), and two held-out off-topic questions score above the weakest on-topic one, so no floor can stop them.
- **The route line's cost estimate counts web searches (#245).** With `--web` and an API key, while a `/budget` is set, the per-turn estimate priced tokens only, though each request may run up to five searches at $0.01. It now reads as a range, for example `~$0.012 to $0.062`, since how many searches a turn makes is the model's choice. Without `--web` the line is unchanged.
- **Hooks can rewrite a call, its result, or stop the turn, with an API key (#248).** A hook's JSON could block a call and add context; three more fields Claude Code honours now work too. PreToolUse `updatedInput` rewrites the call's input, which the tool then checks like the model's own, so a hook cannot widen a read past the project. PostToolUse `updatedToolOutput` (or `updatedMCPToolOutput`, as text or an object's `stdout`) replaces what the model gets back. `continue: false` ends the turn as Ctrl+C does, showing its `stopReason`.

### Changed

- **A read-only tool call repeated in the same turn is not sent again, with an API key (#326).** Every round of a turn resends the turn's tool results, so a `read_file`, `grep`, `list_files` or `fetch_chunk` the model repeated with the same input added the same output (up to 40,000 characters) again, paid for on every later round. The repeat now gets a one-line note naming the earlier result. A `shell` or MCP call in between, which may change files, makes the next read run again, and a call that failed is tried again. How often the model repeats a call was not measured; that needs live API runs (#85).
- **A Gemini reply streams in as agy writes it (#328).** llm_light waited for agy to exit behind a spinner and printed the reply in one piece, so nothing showed for the 15 to 120 seconds a reply takes, and `-p --output-format stream-json` sent one text event at the end. agy's own stream-json output carries the reply as text deltas, which now go to the screen, or to the stream-json output, as they arrive. Live, a three-paragraph reply arrived as 63 text events, the first 3 seconds before the end, where the previous version sent 1. agy's tool check still runs on the whole output afterwards, so a forbidden tool still fails the turn. Codex is unchanged: `codex exec --json` sends its reply in one event, so there is nothing earlier to show.
- **A hook's `defer` refuses the call instead of letting it run, with an API key (#308).** A PreToolUse hook answering `permissionDecision: "defer"` was ignored, so the call it meant to hold back ran. Claude Code ends a `-p` turn there and resumes the call later; llm_light cannot resume a turn at a tool call, so it now refuses the call as it refuses `ask`, and the model reads the hook's reason and that the call was deferred. Resuming a deferred call stays open in #308.
- **A project's `.env` key no longer overrides your subscription login (#277).** llm_light read `./.env` before the login, so in a project that keeps `ANTHROPIC_API_KEY` in `.env` for the app it builds, a subscriber was switched to that key and billed per token. The order is now `ANTHROPIC_API_KEY`, `~/.anthropic`, the login, then `./.env` only when there is no login. The startup header says when a `.env` key was not used; export `ANTHROPIC_API_KEY` to use it.

### Fixed

- **Retrieval charges a summary-only chunk its summary line, not its code (#329).** Only the first chunks of the context show code (none at low effort, one at medium, two at high and max); the others are one summary line each. Selection charged every chunk its full body, so at low effort one long function could use the whole 1,500-token budget and the context named a single file. On the 43 fixture questions (static index, llm_light's real rendering), the answering file reached the context for 20 of 37 instead of 19 at the routed effort, 24 instead of 21 at medium for every question, and 19 instead of 18 at low, for 5% more retrieved tokens at the routed effort (13,276 to 13,938; about 20 more per low-effort question).
- **A retrieved file's preamble is cut at 25 lines and loses its comments (#323).** The lines before a file's first symbol went with its retrieved code verbatim and uncapped: `tools.py` sent 146 lines (about 1,600 tokens), mostly the tool schemas the API already receives, and 16 of this repository's 43 Python modules had preambles over 1,200 characters. Selection charged all of it, so one such file could use half a medium budget. The preamble is now comment-stripped like the code under it and cut at 25 lines or 1,200 characters, with a line saying how many more there are, and both selection passes charge that size. `benchmark_models.py --budgets`, which renders every selected chunk in full, sent 3% to 19% fewer tokens per budget and found the answering file more often at the low and medium budgets (low: 18 to 19 of 25 identifier questions and 9 to 11 of 12 paraphrases; medium: 20 to 21 of 25), the same at high and max. Through llm_light's own rendering, which shows code for the top one or two files only, retrieved context for the 43 questions fell 3.5% (13,791 to 13,313 tokens; 6% at high effort; low effort rose from 61 to 68 as more files fit in its list).
- **Retrieval no longer resends an `@file` attachment's code, or answers a greeting with code (#324).** A file attached with `@path` goes with the question whole, yet retrieval still picked its chunks, often first: on six `@file` questions about this repository, 12 of the 56 retrieved chunks were copies of the attached file, and for one question all 7 were. Those chunks are now dropped after selection; nothing is pulled in to replace them, since a version that did added 15% more context, mostly the same few loosely related files. Retrieved context for the six went from about 5,157 to 5,087 tokens, and to none for the question whose chunks were all copies. A greeting or meta request ("hi", "help", "compact"), already routed to Haiku at low effort, now retrieves nothing (it sent up to 82 tokens of whatever "hi" matched).
- **A large attachment is sent once, not on every later turn (#322).** An `@file`, piped text, `!command` output or a `/review` diff went into the conversation history in full, so up to 50,000 characters were sent again with each of the next six turns, saved to disk, and kept as they were even after an edit changed the file. The turn it is attached to still gets all of it; the history keeps a note naming each attached file and its line count, and the first and last 750 characters of anything else longer than `HISTORY_CONTEXT_CHARS` (1,500), so the error at the end of a build log survives. Through the real `chat()` path with `@llm_light/main.py` (50,106 characters) and five short follow-ups, the history the follow-ups sent fell from 268,513 to 2,213 characters (about 67,000 to 550 tokens). On a resumed subscription session the CLI keeps its own transcript, so this changes what is resent only when the session starts over. How follow-up answers compare without the file was not measured.
- **`grep`, `list_files`, `@` completion and the affected-test search leave out what `.gitignore` excludes (#325).** Only the skeleton and the index honoured it (#267); the API-key tools, `@` completion and the tests run after an edit walked the directory and skipped only the built-in folder names, so a gitignored build, coverage or `*.egg-info` folder showed up in tool results and completion, and a test generated into one could be run. In a git work tree they now use git's own list (`git ls-files --cached --others --exclude-standard`); outside one nothing changes, except that the affected-test search no longer walks into `node_modules` and other skipped folders before filtering. On three local repositories, `list_files` in one went from 300 entries, cut off at its cap, to the complete 212; in this repository it dropped the 6 `llm_light_cli.egg-info` files.
- **`/review` and `/run` route on their instruction, not on the diff or output (#320).** Both put up to 50,000 characters of diff, or the command's output, into the question itself, where the router scored its file names, its length and words like "fix" or "security", and retrieval embedded it. On real diffs from this repository, three of four `/review` turns and a failing pytest log under `/run` routed to Opus at max effort (the top-tier prompt, a 9,000-token retrieval budget); with the diff and output sent after the question, as `@file` contents are, they route to Sonnet at high effort (6,000). Measured with `route_query()` only: what retrieval returns for the shorter question was not measured.
- **An unknown flag stops the run instead of being dropped (#321).** `main()` ignored what the parser did not recognise, so `--plan` started in the writable default mode rather than read-only plan mode, and `--modle haiku "hi"` sent "haiku hi" to the model as a billed question. It is now a usage error (exit 2) before anything starts, naming the closest flag when there is one (`--modle`: did you mean `--model`?). A question that starts with `-` goes after `--`. An unambiguous prefix of a real flag, such as `--permission-mod plan`, still works, as it did before.
- **An idle session stops warming the cache, and never past your `/budget` (#319).** With an API key the heartbeat re-read the prompt cache every 55 minutes for as long as the terminal stayed open: a session left over a weekend sent 64 paid requests. It now stops after `MAX_IDLE_WARMS` warms with no question in between (default 20, about 18 idle hours, so an overnight gap still finds its cache; `LLM_LIGHT_MAX_IDLE_WARMS`, 0 turns warming off), sends none once `/budget` is reached, and sends none once the entry has expired, for example after the machine slept: that warm was a 1-hour write at twice the input price, paid even if you quit right after. In `benchmark_cache_warming.py --idle 60 --no-return` (Sonnet, 6,282-token prefix) the session cost $0.0650 before and $0.0377 after, and it no longer grows with the idle time. The price: a question 19 to 60 hours later writes the cache again ($0.0387 before, $0.0628 after at 20 hours).

- **Two SEARCH/REPLACE blocks for one file now both land (#260).** Each block was resolved against the file on disk, not the result of the block before it, and every result was written to the same path, so one write won and the other changes were lost while the commit message claimed them all. The system prompt asks for exactly this form ("Use multiple blocks for multiple changes, even within the same file"). A file's blocks now apply in order, the syntax check sees the combined result, and the file gets one diff, one write and one commit entry. A block whose SEARCH no longer matches after an earlier block is an error the turn retries. Tested in `tests/unit/test_editor.py` (`TestSeveralBlocksOneFile`), which failed 5 of 5 before the fix.
- **Chunks start and end where their function does, also after non-ASCII text (#262).** Chunk bodies were sliced from the text with tree-sitter's offsets, which count UTF-8 bytes, so every non-ASCII character in a file (an arrow or a dash in a comment) moved each later chunk that many characters on: on this repository 260 of 634 function chunks started mid-name and ran into the next statement. That text was embedded, retrieved, returned by `fetch_chunk` and copied into SEARCH blocks that could not match. Now: 0 of 635. The index cache records a chunk format, so a cache from an earlier version is rebuilt once on the next start. Tested in `tests/unit/test_parsing.py` and `tests/unit/test_indexer.py`.
- **The router matches words, not parts of words (#263).** Its keyword sets were tested with `s in q`, so "this" held the greeting "hi" and "fix this bug", "refactor this function" and "rename this method" took the greeting route to Haiku at low effort; with `ROUTE_ONCE` that kept the whole session on Haiku. "address" held "add", "prefix" held "fix", "builder" held "build" and "logical" held "logic", so "what does the address prefix builder do" went to Opus at max and raised the top-tier prompt. Signals now match whole words, each with the word forms it stands for (`fix`, `fixes`, `fixed`, `fixing`), and the greeting route needs the whole question to be the greeting. Measured with `tests/benchmarks/benchmark_router.py` (static embedder): all 43 questions in `tests/fixtures/repo_questions.json` route as before; the three edit requests now go to Sonnet at high, the two lookups to Haiku at low.
- **An edit changes only the lines it names (#265).** Applying a SEARCH/REPLACE read the file with universal newlines and `errors="ignore"` and wrote it back with the platform's line ending, so on Windows an LF file came back CRLF on every line (`git show --numstat`: 3 lines changed for a one-line edit), on Linux and macOS a CRLF file came back LF, and a byte that is not UTF-8 (a Latin-1 `\xe9` in a comment) was dropped from a line the edit never touched. Now an existing file keeps its own line ending and every byte the edit did not name; a new file still gets the platform's ending. Tested byte for byte in `tests/unit/test_editor.py` (`TestEditKeepsOtherBytes`): an LF file, a CRLF file and a file with one non-UTF-8 byte.
- **Agent edits to files with a space or a non-ASCII character in the name, or in a new directory, are shown and committed (#269).** `git_manager.get_modified_files()` split the text of `git status --porcelain`, which quotes such paths (`"my file.py"`, `"caf\303\251.py"` for café.py) and reports a new directory as one entry (`newpkg/`). On a subscription, after the agent edited such files, llm_light showed no diff, called them "deleted by the agent", failed to stage the first one and committed nothing, so `/undo` and `/rewind` had nothing to take back. It now reads `--porcelain -z --untracked-files=all`: unquoted paths, one per file, and a rename's new path. Tested against a real repository in `tests/unit/test_git_manager.py` (`TestModifiedFilesInRealRepo`), including the commit itself.
- **Each function gets its own dense vector (#264).** A chunk's text starts with the file's preamble (imports, constants), and all-mpnet-base-v2 reads only its first 384 tokens, so in 54% of this repository's function chunks the body was never embedded and all 40 functions of `llm.py` had one vector. The dense model now embeds the path and the body; the chunk the model is shown is unchanged, and the static model keeps the full text (body-first there sent context for off-topic questions). `tests/benchmarks/benchmark_models.py` on the default static + all-mpnet-base-v2: the right file reaches the context for 19 of 25 identifier questions (from 17) and 10 of 12 paraphrases (from 9), with a median of 3 files sent instead of 4; one more of 6 off-topic questions now gets context (#287). Every cache is re-embedded once on the next start.
- **Retrieved code keeps its strings (#266).** Comments were removed from retrieved code with regexes that knew nothing about strings, so `"#ff8800"` became `"`, every `"https://..."` in Java, JavaScript, TypeScript, Go and Rust was cut at `//`, and Go's `regexp.MustCompile("a//b")` lost its tail. Comments are now taken from the tree-sitter parse, which knows a comment from a string, also in a single method body. On this repository 87 of 3,398 chunks now keep text they lost, for +0.26% retrieved-context tokens. Without a grammar the old regexes remain the fallback. That copied code still has no comments, so a SEARCH block built from it can miss (#290).
- **The project walk leaves out what `.gitignore` excludes, and no longer descends into skipped directories (#267).** It ran `Path(".").rglob("*")` and filtered afterwards, so a `venv`, `dist` or generated-code directory was indexed, embedded and listed in the skeleton, and `node_modules` was walked on every start (46,102 paths in one Node project to keep 2,759). In a git work tree the walk is now `git ls-files --cached --others --exclude-standard`; elsewhere `os.walk` prunes skipped directories. `venv` and `dist` join `SKIP_DIRS`, which the API-mode tools and the affected-test search now share instead of keeping their own lists. On this repository: 252 files to 246, about 1,033 to 1,002 skeleton-tree tokens, and the walk from 507 ms to 25 ms.
- **The skeleton's directory tree follows the files on disk (#268).** The project walk was cached at startup and never refreshed, so the tree in the system prompt kept deleted files and missed new ones, including a file the model had created a turn earlier, and a notebook added mid-session never brought in `NotebookEdit`. A tree refresh (the watcher's create, delete and move events) and a full skeleton rebuild now walk again; with #267's `git ls-files` that takes about 25 ms on this repository. Tested in `tests/unit/test_skeleton.py` (`TestTreeFollowsTheDisk`), including a create event through the real watcher handler.
- **Dense-only mode works on large projects again (#306).** With `LLM_LIGHT_HYBRID=0`, a project of 200 or more files got `nomic-ai/nomic-embed-text-v1.5`, which fails on its first encode with the transformers 5 that `requirements.txt` now installs (`'NomicBertModel' object has no attribute 'get_extended_attention_mask'`). It now gets all-mpnet-base-v2, the dense model the default hybrid mode uses. The retrieval benchmark's own copy of the choice changes with it. The default hybrid mode was not affected.
- **Importing llm_light no longer patches `pathlib.Path.unlink` for the whole process (#278).** The package replaced it with a version that swallowed `PermissionError`, a workaround for a test sandbox, so in llm_light and in every library a file that could not be deleted looked deleted. The patch is gone; the suite passes on Windows without it. Pruning old saved conversations, the one best-effort delete that could now fail into a command, skips a file it cannot remove.
- **The retrieval budget counts what is sent (#288).** A second chunk from a file already in the context was charged its whole text, file preamble included, though the context sends that preamble once per file, so the budget filled before the context did. It is now charged its body. `benchmark_models.py --budgets` (which now reports rendered tokens): right file sent at high effort 33 of 37 instead of 32, other efforts unchanged, mean tokens sent within 1%.
- **A reply cut off at the output limit no longer applies half its edits (#271).** With an API key, a reply that stopped at `max_tokens` inside an edit block came back with only the blocks before the cut, which were applied and committed without a word: one file of a two-file refactor. The stop reason now reaches the turn: a cut-off reply's edits are not applied, and llm_light says the reply was cut off. A refusal gets a line too. Not checked against the live API (#71).
- **A subscription turn no longer stalls when the claude CLI writes a lot to stderr (#273).** llm_light read the CLI's stderr only after it exited, so once the pipe was full (a few KB on Windows, 64 KiB on Linux) the CLI blocked on its next write, its output stopped, and the idle watchdog killed the turn after 5 minutes with "Last stderr: (empty)". stderr is now read on a thread while the CLI runs, keeping the last 20,000 characters for error messages. Tested with a real child process that writes 200,000 bytes to stderr: it hung before and answers in 0.07 s now. Gemini and Codex already read both pipes as they run.
- **`/rewind` removes a turn that began by compressing the history (#274).** `chat()` took the turn's checkpoint before compressing the history, so the checkpoint held the longer length and `/rewind` to that turn cut nothing: it reported success and moved the turn count back, but the question and answer stayed in the conversation. That was turn 8 and every third turn after it. The checkpoint is now taken after compression. Tested through the real `chat()` in `tests/unit/test_session_commands.py`.
- **The agent's edit to a file you were already changing is shown (#275).** On a subscription, llm_light found the agent's edits by comparing the names of dirty files before and after the turn, so a file that already held your uncommitted work was in both lists: the agent's change to it was neither shown nor committed, and nothing said so. The snapshot now records each dirty file's content; such a file's change is shown as a diff from where you left it and marked "not committed", since committing it would mix your work in and `/undo` would take it back too. Files the agent made dirty are committed as before. Tested against a real repository in `tests/unit/test_llm.py` (`TestAgentEditsToDirtyFiles`).
- **An edit that touches an ignored file is still committed, and a refused commit says why (#276).** The auto-commit stopped at the first `git add` that failed, so an edit to `a.py` and an ignored `local_settings.py` left `a.py` staged and nothing committed, with no `/undo`; and when a pre-commit hook refused the commit, its message was dropped. An ignored file is now left out with a note and the rest committed; when staging or the commit fails, git's own message is shown and what the auto-commit staged is unstaged again. Tested against a real repository in `tests/unit/test_git_manager.py` (`TestAutoCommitFailures`).
- **History compression keeps its summary when the model thinks first (#272).** `summarize()` read `response.content[0].text`, and thinking is always on for the summary model, so a thinking block first raised `AttributeError`: compression then dropped the oldest turns with no summary in their place, and `/compact` said it could not summarise. The summary is now the text blocks joined, and an empty one counts as a failure, so `/compact` leaves the conversation as it was. Whether the live API puts a thinking block first for the summary model was not checked (#71).
- **Top-level code is retrievable (#270).** The chunker emitted the file preamble and one chunk per function, and dropped everything else: constants after the first function, class headers and attributes, classes without methods, and JavaScript modules written as `export const load = async (id) => ...`. On `llm_light/` that was 6.4% of non-blank lines, 237 of them in `config.py` with `MODEL_PRICES` and the router constants, so "what are the model prices" had nothing to retrieve. Those runs are now chunks named after their first identifier, a `const` bound to an arrow function is a symbol, and `.jsx`, `.mjs` and `.cjs` are indexed with the JavaScript grammar; 0.4% of lines remain in no chunk. `benchmark_models.py --budgets` on the default retrieval: right file sent 31 of 37 at medium effort (from 29), 33 at high and max (from 34), tokens sent within 1% at every effort. Every cache is rebuilt once on the next start.
- **A SEARCH block that matches nothing is an error, not a guess (#261).** When no exact or indentation-only match existed, any window that looked about 70 to 82% alike was replaced by the whole REPLACE text: a SEARCH for a missing `get_item` overwrote `get_user`, and a SEARCH without a function's comments pasted a second `def total` inside the first, which still passed the syntax check. Now the edit fails, and the retry message quotes the file's nearest lines (path and line range) so the model can copy them exactly; a file the index skips (a dotfile such as `.env`, or anything under a hidden or vendored directory) gets no excerpt, since it goes to the model. Exact, line-ending and indentation-only matches work as before. Tested with both cases in `tests/unit/test_editor.py` (`TestSearchThatMatchesNothing`); two older tests that expected a typo'd SEARCH to be applied now expect the error.

## [0.2.0] - 2026-11-14

### Added

- **Paste a screenshot with `alt+v`.** Claude Code, Codex and Gemini CLI take an image from the clipboard; llm_light needed it saved in the project and typed as `@path`. `alt+v` (and `ctrl+v` where the terminal passes it on) saves the clipboard image in `.llm_light_cache/pastes/`, which git and the index ignore, and puts its `@` path in the prompt, so it is checked and sent like any `@image`. No new dependency: PowerShell on Windows, `osascript` on macOS, `wl-paste` or `xclip` on Linux. Checked live on Windows: a bitmap with the words KIWI 83 put on the real clipboard was saved as a 1,619-byte PNG and the subscription agent read the words back; a text clipboard gave "No image on the clipboard". macOS and Linux were not run (#239).
- **Your own instructions for every project.** Claude Code reads `~/.claude/CLAUDE.md`, Codex `~/.codex/AGENTS.md` and Gemini `~/.gemini/GEMINI.md`; llm_light had nothing of the kind, and keeps `~/.claude/CLAUDE.md` from its agent because that file names tools llm_light does not have. Now `~/.llm_light/instructions.md` goes with every question, for every provider; `/memory user` opens it, and startup names it. Never read from a project. Without the file requests are unchanged. Checked live: with a one-line file asking for a codeword, the subscription answer ended with it in 2 of 2 runs and in 0 of 2 without, for 40 more tokens a request (4,251 to 4,291); Codex followed it too.
- **`--add-dir` and `/add-dir` let the agent read another directory.** The agent could read only the project, so a question about how it uses a sibling repository or a shared library had no answer. `--add-dir ../shared-lib` (repeatable), or `/add-dir` in a session, lets it use `Read`, `Grep` and `Glob` there in every permission mode, but not write: an edit outside the project would skip llm_light's diff, commit and `/undo`. It uses read rules, not the `claude` CLI's own `--add-dir`, which also allows writes. With an API key llm_light's own `read_file`, `list_files` and `grep` reach the directories too (#236): an absolute path, or a grep glob that starts with the directory, which the question explains; project paths stay relative and the tool descriptions are unchanged, so the cached prefix is too. A `..` or a symlink that leaves the directory is refused, as in the project. Tested through `tools.run_tool`; no keyed live turn yet (#71). Checked live with claude 2.1.322 in `acceptEdits` mode: without the flag reads were refused; with it `Read` and `Grep` found the planted values and `Write` was refused.
- **Choose which MCP tools may run (#220).** Every tool of a server in `~/.llm_light/mcp.json` ran without asking, so a server with a write tool (post a comment, push, delete a row) could be called by a turn steered by text in the repo. An optional per-server `"allow": ["get_issue", "search_*"]` narrows it: on a subscription a tool off the list is refused, and with an API key it is not offered, which also saves its tokens. The startup line names what each server may run. Checked live on the subscription with claude 2.1.322: with `allow` set to `get_secret`, and again to `get_*`, a probe server's read tool ran and its write tool was refused and left no marker file; without `allow` both ran.

Checked live on the subscription with Haiku: a `PostToolUse` and a `Stop` hook ran, and a blocking `PreToolUse` hook's message came back as the answer.

A named conversation is never pruned by the keep-10 limit. An unknown name is a usage error that lists the names there are.

API-key mode was checked through the real `mcp` SDK, a real stdio server and the real `anthropic` SDK against a stub endpoint; no key was available for a live turn. - **`/loop ... --until "<cmd>"` stops when a command passes (#194).** `/loop 5 --until "python -m pytest -q" fix the failing tests` runs the check before each turn, so one that already passes spends nothing, and hands a failure's output to the next turn. Checked live on the subscription with Haiku: the loop stopped after the turn that made a real check pass. `/loop` still holds the prompt while it runs.

### Fixed

It now ignores itself. An existing cache gets this the next time the index saves.
- **`-p` now exits non-zero when an edit never lints.** After 3 attempts with syntax errors it applied nothing and exited 0, so a script took it for success.

On Linux a 500 kB prompt with a 200 kB system prompt failed before and arrived whole after, through a stand-in for the CLI, since no signed-in `claude` was available on Linux or macOS.

## [0.1.0]

The first release on PyPI, as `llm-light-cli`: `pipx install llm-light-cli` or `uv tool install llm-light-cli`. The command is still `llm-light`. It needs Python 3.12 or newer, and the first install downloads PyTorch (about 1.5 GB) through `sentence-transformers`.

### What it does

- **Interactive and one-shot CLI** (`llm-light`, with `claude-light` kept as an alias) for asking about and editing the codebase in the current directory. Questions can be typed, passed as an argument or piped in; `--continue` resumes the project's previous conversation.
- **Providers**: Claude (default; API key or Pro subscription through `claude auth login`), Gemini through the Antigravity CLI `agy`, and Codex through `codex login`, chosen with `--provider`.
- **Retrieval**: tree-sitter splits Java, Python, Go, Rust, JavaScript and TypeScript into one chunk per method. Each question gets the top-K chunks from a hybrid static and dense index, and the agent can fetch more with `fetch_chunk`.
- **Prompt caching**: the project skeleton sits in a cached system prompt, with cache breakpoints after the history and the retrieved chunks. In API-key mode the cache is warmed once per TTL, and only for the model the turns use.
- **Routing**: each question goes to Haiku, Sonnet or a top tier (asked first), and the first turn's model is kept for the session. `--model` pins a model, and `/budget` caps spend.
- **Editing**: edits are lint-checked, shown as a diff and auto-committed as `Claude: [summary]`. `/undo` reverts the last such commit. Permission modes are `default`, `acceptEdits` (`-y`), `plan` and `bypassPermissions` (`--dangerously-skip-permissions`).
- **Shell**: the agent runs only commands that start with an `--allow-command` prefix. Commands that chain, pipe, redirect or substitute are refused.
- **Optional prompt compression** with LLMLingua: `pipx install "llm-light-cli[llmlingua]"`.
